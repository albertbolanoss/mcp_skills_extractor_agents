# SPEC: Evidence-Grounded Technical Skills Extraction & Evaluation (High-Performance Edition)

## 1. Business Goals & Performance Targets
Extract canonical technical skills and their associated attributes (`seniority_level`, `experience_years`, and `required` for job postings) from plain-text IT resumes (`resume`) and job descriptions (`job_posting`) with zero hallucinations and low end-to-end latency.
Both Extractor and Evaluator agents must actively attempt to determine `seniority_level` and `experience_years` using explicit statements and verifiable contextual evidence (such as work-history date ranges and role seniority). Every extracted field must include a granular evidence structure (`grounding_text`, `justification`, `evaluator_justification`, `accuracy`), while strictly minimizing output token verbosity through schema auto-hydration, delta evaluation merging, and concise justification budgets.

## 2. Architecture Overview (Optimized Hybrid Generator-Evaluator Pattern)
To prevent token explosion, excessive sequential LLM hops, and redundant JSON re-serialization, the pipeline implements a **2-LLM-stage Hybrid Generator-Evaluator architecture with Python Hydration & Delta Merging**:

1. **Generator (Extractor Agent - `sonnet`)**:
   - Extracts candidate technical skills in a single turn (`max_turns=1`, `tools=[]`), normalizing against canonical taxonomies and actively determining `seniority_level`, `experience_years`, and `required` (when `doc_type == "job_posting"`).
   - Produces per-field evidence (`grounding_text` and concise `justification` <= 12 words) for every attribute.
   - **Null-Attribute Token Optimization**: When an attribute cannot be determined with certainty, its root value defaults to `None`, its `grounding_text` is `""`, and its `justification` states why it could not be determined (or is auto-hydrated by Pydantic if omitted/minimal in wire output).
2. **Deterministic Coordinator (Python `asyncio`)**:
   - Short-circuits and returns `[]` immediately if the Extractor returns no items.
   - Splits extracted candidate skills into batches (`EVAL_BATCH_SIZE = 10`) and dispatches concurrent evaluation tasks via `asyncio.gather`.
3. **Batch Evaluator (Evaluator Agent - `haiku`)**:
   - Audits each batch against the source document on a **per-field basis**, assigning an independent `accuracy` score (`0.0` to `1.0`) and concise `evaluator_justification` (<= 12 words) for `skill`, `seniority_level`, `experience_years`, and `required` (when `doc_type == "job_posting"`).
   - Nullifies any unsubstantiated secondary attribute or recovers clearly stated attributes missed by the extractor.
   - **Delta Merge Optimization**: In `_run_evaluator_batch`, Python merges the Evaluator's output with the original Extractor batch item so the Evaluator does not need to re-emit unchanged `grounding_text` and `justification` strings (while remaining 100% compatible with full `TechnicalSkillItem` payloads in unit test mocks).
4. **Deterministic Synthesizer (Pure Python)**:
   - Filters out items where `evidences.skill.accuracy < 0.7` (`ACCURACY_THRESHOLD`).
   - Nullifies secondary attributes whose field-level `accuracy < 0.7` and resets their `grounding_text = ""`.
   - Applies canonical normalization functions (`normalize_technical_skill`, `normalize_seniority_level`).
   - Enforces document-type structural rules (`required` included only for `job_posting`), and returns the serialized list of dictionaries.

## 3. Functional Requirements

### 3.1 Modular Separation of Concerns
- Decouple the agent definitions, prompts, Pydantic schemas, and orchestration pipeline from the MCP tool definition file:
  - `src/mcp_skills_extractor_agents/server/tools/technical_skill_extraction.py` (or `src/tools/extract_technical_skills.py`): Contains only the `@mcp.tool()` entrypoint wrapper that delegates execution to `run_technical_skills_pipeline`.
  - `src/mcp_skills_extractor_agents/agents/technical_skills/__init__.py`: Exports `run_technical_skills_pipeline`.
  - `src/mcp_skills_extractor_agents/agents/technical_skills/schemas.py`: Contains Pydantic v2 data models (`FieldEvidence`, `SkillEvidences`, `TechnicalSkillItem`) with resilient pre-validation hydration.
  - `src/mcp_skills_extractor_agents/agents/technical_skills/prompts.py`: Contains static system prompts, user prompt builders, and JSON correction prompts for both Extractor and Evaluator.
  - `src/mcp_skills_extractor_agents/agents/technical_skills/definitions.py`: Contains `EXTRACTOR_AGENT_DEFINITION` (`sonnet`) and `EVALUATOR_AGENT_DEFINITION` (`haiku`).
  - `src/mcp_skills_extractor_agents/agents/technical_skills/orchestrator.py`: Contains `ClaudeSDKClient` query helpers, cached environment loading, retry loops, batching coordinator, delta merger, and deterministic synthesizer.

### 3.2 Active Evidence-Based Extraction (Generator)
- Normalize extracted skills against `COMMON_TECHNICAL_SKILLS` and seniority levels against `COMMON_SENIORITY_LEVELS`.
- Actively attempt to determine `experience_years` using:
  1. **Direct statements** (e.g., `"5+ years of Python experience"` -> `5`).
  2. **Chronological calculation** from explicit role date ranges where the skill was used (e.g., `"Backend Developer (2021 - 2024): Developed APIs in FastAPI"` -> `3`, quoting the date header and skill line in `grounding_text` and showing the calculation in `justification`, e.g., `"2021-2024 role duration equals 3 years"`).
  3. **Role/posting requirement propagation** in `job_posting` documents when a global year requirement explicitly covers the listed core stack.
- Actively attempt to determine `seniority_level` using:
  1. **Explicit proficiency descriptors** (e.g., `"Expert"`, `"Advanced"`, `"Senior"`, `"Intermediate"`, `"Junior"`).
  2. **Contextual role/scope evidence** (e.g., applying the skill as a `"Lead/Senior Architect"`, mentoring teams, leading system design, or aligning with verified `experience_years` in context).
- Populate `required` (`true` for mandatory/core qualifications, `false` for optional/preferred/nice-to-have) when `doc_type == "job_posting"`.
- **Job Posting Default `required` Rule**: In job postings, the `required` field specifies whether a skill is required or desirable; if it is not explicitly stated as optional/desirable/nice-to-have, consider it `required = true` and note this in `justification` and evaluation.
- **Uncertainty & Conciseness Rule**:
  - If `seniority_level` or `experience_years` cannot be determined with certainty from the text, set the root field to `null`, still return its evidence object in `evidences`, set `"grounding_text": ""`, and provide a concise `"justification"` explaining why the value could not be determined from the document.
  - Keep every `justification` concise (<= 12 words) and `grounding_text` limited to the exact supporting line/date snippet to minimize output token generation time.
- Populate `evidences` with per-field objects (`skill`, `seniority_level`, `experience_years`, and `required` if `doc_type == "job_posting"`), each initialized with:
  - `grounding_text`: Verbatim quote from the source document supporting the field (or `""` if the field is `null`).
  - `justification`: Brief explanation (<= 12 words) of how the quote supports the extracted value, or why `grounding_text` is empty.
  - `evaluator_justification`: Initialized to `null`.
  - `accuracy`: Initialized to `-1.0` prior to evaluation.

### 3.3 Parallel Batch Evaluation & Delta Merging (Coordinator & Evaluator)
- Short-circuit immediately and return `[]` if the Extractor Agent returns an empty list (do not invoke the Evaluator).
- Partition extracted items into batches of up to 10 items (`EVAL_BATCH_SIZE = 10`) and evaluate batches concurrently using `asyncio.gather`.
- Strip pre-evaluation placeholders (`accuracy` and `evaluator_justification`) before serializing the batch into the Evaluator prompt to save input tokens.
- For each item in a batch, the Evaluator Agent must audit **every field independently** (`skill`, `seniority_level`, `experience_years`, and `required` for `job_posting`) against the full source document:
  - **`skill` evaluation**:
    - Set `evidences.skill.accuracy` between `0.0` and `1.0` (`1.0` = explicitly present and supported by `grounding_text`, `0.0` = hallucinated skill not in document).
    - Provide a concise `evidences.skill.evaluator_justification` (<= 12 words).
  - **Secondary fields evaluation (`seniority_level`, `experience_years`, `required`)**:
    - **When extracted value is non-null**: Verify that `grounding_text` exists in the source document and that the value (including date math or contextual derivation) is accurate. If valid, set field `accuracy` (`0.7` to `1.0`) and confirm in `evaluator_justification`. If hallucinated or unsubstantiated, set the field value to `null`, set `grounding_text` to `""`, set field `accuracy` (`0.0` to `< 0.7`), and explain the rejection in `evaluator_justification`.
    - **When extracted value is `null` (`grounding_text == ""`)**: Verify whether the document genuinely lacks sufficient evidence. If the abstention is correct, keep the field `null` and `grounding_text: ""`, set field `accuracy = 1.0`, and confirm in `evaluator_justification` that the attribute is not determinable from the text. If the Extractor missed clear evidence present in the document, populate the corrected field value and verbatim `grounding_text`, set `accuracy = 1.0`, and document the recovery in `evaluator_justification`.
- **Delta Merge in Orchestrator**:
  - To prevent the Evaluator from wasting output tokens repeating unchanged `grounding_text` and `justification` fields, `_parse_evaluated` merges each raw dict returned by the Evaluator with its corresponding source item from `batch`: if `grounding_text` or `justification` is omitted in the Evaluator's response for an un-nullified field, it inherits the Extractor's original `grounding_text` and `justification` before running `TechnicalSkillItem.model_validate`.

### 3.4 Deterministic Synthesis (Synthesizer)
- Retain only items where `evidences.skill.accuracy >= 0.7` (`ACCURACY_THRESHOLD`).
- For each secondary attribute (`seniority_level`, `experience_years`, `required`):
  - If `evidences.<field>.accuracy < 0.7`, force the root attribute `item.<field> = None` and set `evidences.<field>.grounding_text = ""`.
  - If `item.<field> is None`, guarantee `evidences.<field>.grounding_text == ""`.
- Apply `normalize_technical_skill` to `item.skill` and `normalize_seniority_level` to `item.seniority_level` (when not `None`).
- **Document-Type Serialization Rule**:
  - When `doc_type == "job_posting"`: Return `skill`, `seniority_level`, `experience_years`, and `required` at the root level (preserving `None` as JSON `null` when undetermined) and all four corresponding keys inside `evidences`.
  - When `doc_type == "resume"`: Omit `required` from both the root dictionary and the `evidences` object, while always returning `skill`, `seniority_level`, and `experience_years` at both levels.

## 4. Data Contracts & Pydantic v2 Schemas
File: `src/mcp_skills_extractor_agents/agents/technical_skills/schemas.py`

~~~python
from typing import Any
from pydantic import BaseModel, Field, model_validator

DEFAULT_NULL_JUSTIFICATION = "Not explicitly stated or verifiable from chronological or role context in the document."


class FieldEvidence(BaseModel):
    """Evidence and audit trail for an individual extracted field."""

    grounding_text: str = Field(
        default="",
        description=(
            "Verbatim quote from the source document supporting the field value, "
            "or empty string if the field could not be determined."
        ),
    )
    justification: str = Field(
        default=DEFAULT_NULL_JUSTIFICATION,
        description=(
            "Extractor's rationale for the extracted value, or explanation of why "
            "grounding_text is empty when the value cannot be determined."
        ),
    )
    evaluator_justification: str | None = Field(
        default=None,
        description="Evaluator's audit rationale explaining verification, correction, or nullification.",
    )
    accuracy: float = Field(
        default=-1.0,
        description="Verification score assigned by the evaluator (0.0 to 1.0), or -1.0 prior to evaluation.",
    )

    @model_validator(mode="before")
    @classmethod
    def _hydrate_defaults(cls, data: Any) -> Any:
        if isinstance(data, dict):
            justification = data.get("justification")
            if justification is None or (
                isinstance(justification, str) and not justification.strip()
            ):
                return {**data, "justification": DEFAULT_NULL_JUSTIFICATION}
        return data


class SkillEvidences(BaseModel):
    """Per-field evidence breakdown for a single technical skill item."""

    skill: FieldEvidence
    seniority_level: FieldEvidence = Field(
        default_factory=lambda: FieldEvidence(
            grounding_text="", justification=DEFAULT_NULL_JUSTIFICATION
        )
    )
    experience_years: FieldEvidence = Field(
        default_factory=lambda: FieldEvidence(
            grounding_text="", justification=DEFAULT_NULL_JUSTIFICATION
        )
    )
    required: FieldEvidence | None = None

    @model_validator(mode="before")
    @classmethod
    def _ensure_secondary_evidences(cls, data: Any) -> Any:
        if isinstance(data, dict):
            out = dict(data)
            for key in ("seniority_level", "experience_years"):
                if out.get(key) is None:
                    out[key] = {
                        "grounding_text": "",
                        "justification": DEFAULT_NULL_JUSTIFICATION,
                    }
            return out
        return data


class TechnicalSkillItem(BaseModel):
    """Canonical representation of an extracted and evaluated technical skill."""

    skill: str
    seniority_level: str | None = None
    experience_years: int | None = None
    required: bool | None = None
    evidences: SkillEvidences
~~~

## 5. Technical Rules, Performance Guardrails & Orchestrator Design

### 5.1 Prompt Engineering & Prefix Caching (`prompts.py`)
- Inject flattened `_CANONICAL_SKILLS` and `COMMON_SENIORITY_LEVELS` into the static `system_prompt` in `prompts.py` at module import time to leverage LLM prefix caching and avoid runtime MCP resource serialization overhead.
- Enforce strict output conciseness in both system prompts:
  - Extractor: Keep `grounding_text` to the shortest verbatim snippet proving the attribute, and `justification` to `<= 12 words`.
  - Evaluator: Keep `evaluator_justification` to `<= 12 words`. Allow omitting unchanged `grounding_text` and `justification` keys during evaluation (or preserving them concisely) so output generation completes in minimal time.

### 5.2 SDK Session Optimization & Self-Correction Retry Loop (`orchestrator.py`)
- **Environment Caching**: Cache `get_agent_environment(get_agent_settings()).env` via `@lru_cache(maxsize=1)` or a module-level singleton so parallel evaluator batches do not repeatedly reconstruct settings.
- **Single-Turn Fast Execution**: Pass `max_turns=1` and `tools=agent_definition.tools or []` into `ClaudeAgentOptions` to prevent unnecessary tool discovery overhead.
- **Self-Correction Retry Loop**: Maintain the multi-turn session retry mechanism (`max_retries: int = 2`) on the active `ClaudeSDKClient` instance whenever `json.loads`, `_extract_json_array`, or Pydantic `model_validate` raises `(json.JSONDecodeError, ValidationError, ValueError)`.
- **Delta Merge Helper (`_merge_evaluated_item`)**:
  In `_parse_evaluated(raw_text: str, original_batch: list[TechnicalSkillItem]) -> list[TechnicalSkillItem]`, verify `len(raw_items) == len(original_batch)`. Before validating each item with `TechnicalSkillItem.model_validate`, merge each evidence sub-dictionary with the corresponding `original_batch[i].evidences` field so that if the Evaluator omits `grounding_text` or `justification` to save tokens, the Extractor's original values are preserved (while explicit changes or `""` overrides from the Evaluator take precedence).

~~~python
def _merge_evaluated_item(
    raw_item: dict, original: TechnicalSkillItem
) -> TechnicalSkillItem:
    """Merges Evaluator delta/output with Extractor's original item before Pydantic validation."""
    merged = {
        "skill": raw_item.get("skill", original.skill),
        "seniority_level": raw_item.get("seniority_level", original.seniority_level),
        "experience_years": raw_item.get("experience_years", original.experience_years),
        "required": raw_item.get("required", original.required),
    }
    orig_ev_dump = original.evidences.model_dump()
    raw_evidences = raw_item.get("evidences") or {}
    merged_evidences: dict = {}

    for field_name, orig_field_ev in orig_ev_dump.items():
        raw_field_ev = raw_evidences.get(field_name)
        if orig_field_ev is None and raw_field_ev is None:
            merged_evidences[field_name] = None
            continue
        base_ev = dict(orig_field_ev or {})
        if isinstance(raw_field_ev, dict):
            for k, v in raw_field_ev.items():
                if v is not None:
                    base_ev[k] = v
        merged_evidences[field_name] = base_ev

    merged["evidences"] = merged_evidences
    return TechnicalSkillItem.model_validate(merged)
~~~

## 6. Edge Cases
1. **Empty or Non-Technical Document**: Extractor returns `[]`; orchestrator skips Evaluator execution and returns `[]` immediately.
2. **Skill Listed Without Context (Undetermined Seniority/Years)**: A resume has a flat section `"Skills: Python, Docker"` with no dates or proficiency level. Extractor outputs `"skill": "Python"`, `"seniority_level": null`, `"experience_years": null`, populates `evidences.skill.grounding_text = "Skills: Python, Docker"`, and sets `evidences.seniority_level` and `evidences.experience_years` with `"grounding_text": ""` and concise `"justification"`. Evaluator verifies the absence of context and assigns `accuracy = 1.0` to those abstentions.
3. **Chronological & Contextual Derivation**: A resume states `"Senior Backend Engineer (2021 - 2025) - Architected event-driven pipelines using Apache Kafka"`. Extractor determines `"skill": "Apache Kafka"`, `"seniority_level": "Senior"`, `"experience_years": 4`, quoting the block in `grounding_text` and explaining the 2021–2025 duration and Senior role scope in `justification`. Evaluator verifies the math and context and sets `accuracy = 1.0` across all fields.
4. **Valid Skill with Hallucinated Seniority or Experience Years**: Extractor outputs `"skill": "Python", "seniority_level": "Senior", "experience_years": 5` from a line that only says `"Familiar with Python"`. Evaluator sets `evidences.skill.accuracy = 1.0`, sets `evidences.seniority_level.accuracy = 0.0` (or corrects `"seniority_level"` to `"Junior"`/`"Beginner"` if supported) and `evidences.experience_years.accuracy = 0.0`, resets unsupported field values to `null` with `grounding_text = ""`, and documents the audit in each field's `evaluator_justification`.
5. **Completely Hallucinated Skill**: Extractor outputs `"Kubernetes"` when the text only mentions `"Docker"`. Evaluator sets `evidences.skill.accuracy = 0.0`; Synthesizer removes the entire `"Kubernetes"` item from the final output.
6. **Resume vs. Job Posting `required` Handling**: For `doc_type == "resume"`, the Synthesizer strips `required` from both the root item and `item["evidences"]`. For `doc_type == "job_posting"`, `required` is always present at both levels (defaulting to `true` when not explicitly marked as optional/desirable).

## 7. Exclusions (Out of Scope)
- Do not extract soft skills, spoken languages, or certifications in this module.
- Do not implement the Coordinator or Synthesizer as LLM agents; both must remain deterministic Python functions.
- Do not introduce external database persistence or state stores inside this tool execution flow.
